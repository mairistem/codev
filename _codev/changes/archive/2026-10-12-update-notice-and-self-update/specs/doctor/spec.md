## MODIFIED Requirements

### Requirement: `codev doctor` runs a fixed list of read-only checks

`codev doctor` SHALL evaluate the following checks, reported in this order, each
with a stable `id`, and report each one as `ok`, `missing` or `warning`,
with a stable `code` (`ok` when the check passes), a one-line message and,
when not `ok`, a one-line fix naming the exact command or skill:

| id | passes when | otherwise | code | fix |
|---|---|---|---|---|
| `config.rules` | `rules:` has at least one entry, inherited ones included | missing | `rules_missing` | `/codev-configure` |
| `config.language` | `language:` is set in `_codev/config.yaml` | missing | `language_missing` | add `language: <code>` to `_codev/config.yaml` |
| `skills` | every configured workflow has its skill, generated by the running codev version | missing | `skills_missing` or `skills_outdated` | `codev update` |
| `sources` | every inherited git source is pinned in `_codev/codev.lock` and present in the cache, and the lock pins no undeclared source | missing (unpinned or not cached) or warning (undeclared pin) | `source_unpinned` or `lock_stale` | `codev sources update` |
| `codev_version` | the running codev satisfies the project's `codev_version`, when set, and the cached update check knows no newer release | missing (requirement not satisfied) or warning (newer release known) | `codev_version_unsatisfied` or `update_available` | `codev self-update` |
| `specs` | at least one main spec exists | missing | `no_main_spec` | `/codev-propose`, noting that documenting existing behavior is planned work |
| `decisions` | at least one decision is `accepted`, local or inherited | warning | `no_accepted_decision` | `codev decision new "<title>"` |
| `validate` | `codev validate` reports no error and no warning | missing (errors) or warning (warnings only) | `validate_errors` or `validate_warnings` | `codev validate` |
| `claude_md` | `CLAUDE.md` holds the codev managed section | missing | `claude_md_section_missing` | `codev init` |
| `ci` | a file of `.github/workflows/` or `.gitlab-ci.yml` runs `codev validate` | missing | `ci_validate_missing` | `codev init` on GitHub, otherwise add `codev validate --strict` to the pipeline |
| `pr_template` | the pull request template holds the codev managed section — GitHub repositories only | missing | `pr_template_section_missing` | `codev init` |
| `changelog` | `CHANGELOG.md` exists and its managed `[Unreleased]` section matches what `codev changelog` would generate now | warning | `changelog_missing` (no file) or `changelog_outdated` | `codev changelog --write` |

The `pr_template` check MUST be absent from the report when the repository
is not a GitHub repository. A project without any inherited source passes
`sources`. A CI line is recognized when it names `codev` and then
`validate`, so `cargo run --bin codev -- validate` counts.

The `codev_version` check reads the per-user update cache that
`codev status` maintains and never refreshes it: with no cache, or with
`CI` set or `CODEV_NO_UPDATE_CHECK=1`, it only evaluates the requirement.

`codev doctor` MUST NOT write any file or access the network. The only
process it MAY spawn is `git`, for the local, read-only queries the
`changelog` check needs; outside a git repository, that check compares
with every archived change. Outside a codev project, it fails with the code
`no_codev_root`.

#### Scenario: A freshly initialized project

- **GIVEN** a project just initialized with `codev init --yes` outside
  GitHub, without rules, specs or decisions, and no newer codev release
  known
- **WHEN** the user runs `codev doctor`
- **THEN** `config.rules` and `specs` are `missing`, `decisions` is a
  `warning`, `ci` is `missing`
- **AND** `config.language`, `skills`, `sources`, `codev_version`,
  `claude_md` and `validate` are `ok`
- **AND** `changelog` is a `warning` with the code `changelog_missing`
- **AND** no `pr_template` check is reported

#### Scenario: Outdated skills

- **GIVEN** a project whose skills were generated by an earlier codev
  version
- **WHEN** the user runs `codev doctor`
- **THEN** `skills` is `missing` with the code `skills_outdated` and the fix
  `codev update`

#### Scenario: An unpinned git source

- **GIVEN** a project declaring a git source absent from
  `_codev/codev.lock`
- **WHEN** the user runs `codev doctor`
- **THEN** `sources` is `missing` with the code `source_unpinned` and the
  fix `codev sources update`

#### Scenario: CI recognized through `cargo run`

- **GIVEN** a GitHub project whose `.github/workflows/ci.yml` runs
  `cargo run --bin codev -- validate --strict`
- **WHEN** the user runs `codev doctor`
- **THEN** `ci` is `ok`

#### Scenario: Doctor writes nothing

- **GIVEN** any codev project
- **WHEN** the user runs `codev doctor`
- **THEN** no file of the project is created or modified

#### Scenario: Outside a codev project

- **GIVEN** a folder with no `_codev/` above it
- **WHEN** the user runs `codev doctor`
- **THEN** the command fails with the code `no_codev_root`

#### Scenario: CHANGELOG.md up to date

- **GIVEN** a project where `codev changelog --write` was just run
- **WHEN** the user runs `codev doctor`
- **THEN** `changelog` is `ok`

#### Scenario: CHANGELOG.md behind the archive

- **GIVEN** a project whose `CHANGELOG.md` managed section predates the
  latest archived change
- **WHEN** the user runs `codev doctor`
- **THEN** `changelog` is a `warning` with the code `changelog_outdated`
  and the fix `codev changelog --write`
- **AND** the exit code of `codev doctor --strict` is unaffected by it

#### Scenario: Running codev below the project's requirement

- **GIVEN** a project with `codev_version: ">=0.7"` and codev 0.6.0 running
- **WHEN** the user runs `codev doctor`
- **THEN** `codev_version` is `missing` with the code
  `codev_version_unsatisfied` and the fix `codev self-update`

#### Scenario: A newer release is known

- **GIVEN** a project without `codev_version`, and an update cache knowing
  a release newer than the running codev
- **WHEN** the user runs `codev doctor`
- **THEN** `codev_version` is a `warning` with the code `update_available`
  and the fix `codev self-update`
- **AND** no network request is made

### Requirement: `codev status` hints at `codev doctor`

When at least one doctor check is `missing`, the human output of
`codev status` SHALL end with one line on stderr suggesting
`codev doctor`, including when `codev status` fails because no change is
active. The hint MUST NOT appear in the JSON output of `codev status`.

#### Scenario: Hint on a project with missing checks

- **GIVEN** a project with an active change and no main spec
- **WHEN** the user runs `codev status`
- **THEN** stderr ends with a line naming `codev doctor`

#### Scenario: No hint when everything is in place

- **GIVEN** a project where no doctor check is `missing`
- **WHEN** the user runs `codev status --change <name>`
- **THEN** no line names `codev doctor`

#### Scenario: The hint stays out of the JSON

- **GIVEN** a project with an active change and no main spec
- **WHEN** the user runs `codev status --change <name> --json`
- **THEN** stdout is one JSON document and no line names `codev doctor`
