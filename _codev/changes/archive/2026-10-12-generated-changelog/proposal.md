# Proposal: Release notes generated from archived changes — `codev changelog`

## Why

Each archived change already says why and what changed, marks its breaking
changes and carries its spec deltas: a better source for release notes than
commit messages, yet today `CHANGELOG.md` and the GitHub release bodies are
written by hand and drift from the archive. codev should produce the content
of the changelog; choosing versions, tagging and publishing stay with
release tooling.

## What Changes

- The `spec-driven` proposal gains a `## Release note` section, after
  `## Impact`: one or more bullets `- <Category>: <text for end users>`,
  where Category is `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed` or
  `Security`, a breaking item starting its text with `**BREAKING**`; a
  purely internal change writes the single line `None`. The product owner's
  "Done when" criteria require it.
- `codev validate` warns `release_note_missing` when an active change's
  proposal has no `## Release note` section, and reports the error
  `release_note_invalid` for an unknown category, an empty bullet or an
  empty section. Archived changes are never checked.
- `/codev-propose`'s traceability check requires the release note to agree
  with What Changes and with the REMOVED and MODIFIED deltas.
- New command `codev changelog [--since <ref>] [--until <ref>]
  [--format keep-a-changelog|markdown|json] [--release <version>
  [--date YYYY-MM-DD]] [--write]`: lists the release-note items of the
  changes archived between two git refs (by default, since the most recent
  `v*` tag), BREAKING items first, categories in Keep a Changelog order.
  Changes archived without a release note fall back to their What Changes
  bullets under `Changed`, each named in a `release_note_missing` warning;
  a note that removes requirements without a `Removed` or BREAKING item
  raises `release_note_inconsistent`. Outside a git repository, every
  archived change is listed, with a warning.
- `codev changelog --write` keeps `CHANGELOG.md` up to date: the generated
  `[Unreleased]` section lives in a managed section right after the file
  header, created with a standard header when the file is missing, and the
  text outside it is never rewritten. With `--release`, the section becomes
  a dated version block and a new empty managed `[Unreleased]` takes its
  place.
- `_codev/config.yaml` accepts `changelog.exclude`, the archived changes
  already described by hand in `CHANGELOG.md`, which `codev changelog`
  leaves out.
- `codev doctor` gains a `changelog` check (warning only): `CHANGELOG.md`
  exists and its managed `[Unreleased]` section matches what
  `codev changelog` would generate now. To compute it, doctor may run local,
  read-only `git` queries; it still writes nothing and stays offline.
- codev's own release workflow writes the GitHub release body with
  `codev changelog`, built from the tagged source; codev's own
  `CHANGELOG.md` gets its managed section.

## Capabilities

### New Capabilities

- `changelog` — the release note format, the `codev changelog` command, its
  range, content, formats, `--release` and `--write`, and
  `changelog.exclude`.

### Modified Capabilities

- `validation` — release note checks of active changes.
- `doctor` — the `changelog` check, and local read-only `git` queries.
- `skills` — the product owner's release note criterion and the
  traceability check of `/codev-propose`.
- `distribution` — the release body generated by `codev changelog`.

### Removed Capabilities

None.

## Impact

- `codev-core`: release note parser, What Changes extraction, range and
  ordering, rendering, `CHANGELOG.md` splicing (reusing the managed
  sections), the doctor `changelog` check.
- `codev-engine`: release note validation of active changes, archive and git
  facts for the changelog (through the `ProcessRunner` port),
  `changelog.exclude` in the project configuration.
- `codev-cli`: the `changelog` command, its human and JSON outputs (JSON
  contract v1 gains `ChangelogV1`), doctor facts.
- `assets/`: proposal template and instruction, `propose` workflow; the
  installed skills are regenerated.
- `.github/workflows/release.yml`, `CHANGELOG.md`, `_codev/config.yaml`.
- Documentation in English and French: CLI reference, configuration, file
  formats, JSON output, skills, the repository integration and doctor guide,
  a new "Release notes and CHANGELOG" guide, CONTRIBUTING (release process);
  CHANGELOG.

## Release note

- Added: `codev changelog` generates release notes from the archived
  changes — Keep a Changelog, plain markdown or JSON — between two git refs,
  by default since the latest `v*` tag, and `--write` keeps a managed
  `[Unreleased]` section of `CHANGELOG.md` up to date; `--release <version>`
  turns it into a dated version block.
- Added: Proposals carry a `## Release note` section, categorized for end
  users; `codev validate` warns when an active change has none
  (`release_note_missing`) and rejects an unknown category or an empty item
  (`release_note_invalid`).
- Added: `codev doctor` checks that `CHANGELOG.md` matches what
  `codev changelog` generates (`changelog`, a warning only).
- Added: `changelog.exclude` in `_codev/config.yaml` leaves out archived
  changes already described by hand in `CHANGELOG.md`.
