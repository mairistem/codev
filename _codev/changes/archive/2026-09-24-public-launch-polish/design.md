# Design: polish public launch

## Context

See `proposal.md`. **Meta / documentation** change — 8 new files,
2 modified, zero Rust. `skip_specs: true` accepted.

## Decisions

### Decision: **OpenSpec** credit at the top of the README + "Origins" section in `docs/codev.md`

Two locations:

- **README** — a line visible in the first lines seen by a visitor
  discovering the repo: `> Inspired by [OpenSpec](https://github.com/tobyhs/openspec), rebuilt in Rust with its own choices (see `docs/codev.md` § Origins).`
- **`docs/codev.md`** — new **"Origins"** subsection under
  section 1 (Why codev), which details:
  - What comes from OpenSpec — propose/apply/archive cycle, the
    notion of spec deltas, capabilities, ADRs.
  - What was set aside — TypeScript (Rust chosen), hidden
    `.openspec/` (visible `_codev/`), an `openspec` binary of several
    thousand lines (pure core + imperative shell).
  - What is specific to codev — K3 seal, K6 drifts, K7 promotion,
    configurable MCP integration, `codev docs`, prebuilt
    distribution.

**Rejected alternative**: a simple `Prior art: OpenSpec` mention
in the README footer. Rejected — too discreet, insufficient if we
truly want to acknowledge the intellectual debt.

### Decision: `CHANGELOG.md` maintained by hand, not auto-generated

The **Keep-a-Changelog** format is adopted. At each tag, the
maintainer adds a V1.x entry with the changes archived since the
previous version. The CHANGELOG always points to the GitHub Release
for the detailed notes (they are auto-generated by
`generate_release_notes: true` in the workflow).

**Rejected alternative**: a `codev changelog` script that walks
`_codev/changes/archive/` to build the file. Useful someday, but
can wait — the manual version takes 2 minutes per tag.

### Decision: `CODE_OF_CONDUCT.md` = Contributor Covenant 2.1 unmodified

A well-known standard, adopted by thousands of projects (Rust
itself, Node.js, most Apache projects). Reusing the official text
avoids inventing an incomplete charter. Contact: `mairistem` (or
Ludovic's email, to be chosen).

**Rejected alternative**: a home-made version. Rejected — reassures
nobody, costly to maintain.

### Decision: `SECURITY.md` = GitHub Security Advisories, no email

The repo is on GitHub → the official way to report a vulnerability
is **GitHub Security Advisories** (Repo → Security → Advisories →
Report a vulnerability). It is private, versioned, with a CVE if
needed.

A generic email (`security@…`) is a second option for those who
prefer it, but it will not be invented if Ludovic does not already
have a `mairistem.com` domain ready.

**Rejected alternative**: an empty `SECURITY.md` file promising
future handling. Refused — better to promise nothing than to make
an empty promise.

### Decision: `CONTRIBUTING.md` guides through **the codev cycle itself**

A contributor discovering codev sees in `CONTRIBUTING.md`:

1. Fork + clone.
2. `cargo install --path crates/codev-cli` to build from source.
3. `codev init` on the fork (if not already initialized).
4. Create a change: `codev new change <my-idea>` or
   `/codev-propose <my-idea>` in Claude Code.
5. Implement, test (`cargo test --workspace`), archive
   (`codev archive <my-idea>`).
6. Push, open a PR.

**Meta**: codev **uses codev to document itself, maintain itself,
and be contributed to**. Full consistency, and a living
demonstration that the cycle works for a real project.

### Decision: `.github/ISSUE_TEMPLATE/` templates — two forms, not three

- `bug_report.md` — Reproduction, expected behavior, observed
  behavior, environment (`codev --version`, OS).
- `feature_request.md` — Problem it solves, alternative
  considered, scope.
- `config.yml` — disables blank issues (`blank_issues_enabled:
  false`), redirects to Discussions and CONTRIBUTING.

Three forms (bug / feature / question) create friction for the
user. Question → Discussions.

### Decision: README badges — 4 badges, not 10

- **Build status** (GitHub Actions release workflow) — health signal.
- **Latest release** (latest tagged version) — useful for installing.
- **License MIT** — clarifies reuse.
- **Supported platforms** (macOS, Linux, Windows) — frames usage.

Avoid cosmetic badges (rustdoc, code coverage, stars). They can
come later if there is a reason.

## Risks / Trade-offs

- **`CHANGELOG.md` can drift** from the real history if a
  maintainer forgets to update it at a tag. → **Mitigation**:
  add a reminder in the `CONTRIBUTING.md` "Release" section, and
  the GitHub Release remains the fallback source of truth.
- **`CODE_OF_CONDUCT.md` may be perceived as performative** —
  nobody reads it before having a real conflict. → **Accepted
  trade-off**: it is the de facto open source standard, its absence
  would be more noticeable than its presence.
- **The OpenSpec credit may look defensive** ("we stole
  nothing"). → **Framed positively**: "inspired by, rebuilt in
  Rust with its own choices", neutral tone, the Origins section
  gives the details.

## Migration Plan

None. Additive feature, visual opt-in (the visitor sees extra
polish, the existing user notices nothing).
