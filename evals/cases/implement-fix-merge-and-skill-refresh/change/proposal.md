# Proposal: A merge that keeps a modified last requirement whole, and an update that refreshes its own skills

## Why

Two defects found while dogfooding codev. Archiving the change
`measure-consumption` wrote its new requirement into the middle of a line
of the last requirement it modified, cutting a scenario of
`_codev/specs/role-evaluation/spec.md` in two — and `codev validate` let
it pass. And `codev update` left `codev-propose` and `codev-apply` stale,
calling them "edited by hand", whenever the skills' text changed without
a version change, as on every build from source: the fix needed `--force`,
which would also have erased real hand edits.

## What Changes

- A sync or an archive whose delta both modifies the main spec's last
  requirement and adds requirements writes the modified requirement whole,
  then the added ones after it.
- A rendered skill carries a checksum of its own content in its
  frontmatter (`metadata.checksum`). Among skills stamped with the
  running version, `codev update` rewrites one whose content still
  matches its checksum and preserves as edited by hand only one whose
  content no longer matches it; a skill stamped with another version is
  rewritten as today, and a skill rendered before checksums keeps today's
  rule.

## Release note

- Fixed: Archiving a change that modifies a spec's last requirement and adds requirements no longer cuts that requirement in two: the added ones are written after it.
- Fixed: `codev update` refreshes the skills it rendered itself even when their version stamp has not changed, and preserves only the skills edited by hand; each skill now carries a checksum of its content. Skills generated by an earlier codev are rewritten on upgrade as before; on a build from source, skills of the same version without a checksum are still preserved, and one `codev update --force` brings them under the checksum — check `git diff` first, since it also overwrites real hand edits.
- Fixed: Earlier codev versions could cut a spec's last requirement in two when one change both modified it and added requirements; `codev validate` does not detect it, and syncing again does not repair it. If you archived such a change, look at the spec it modified (the diff of the archive) and repair it by hand or with a new `MODIFIED` delta.
