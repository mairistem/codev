Comment ça marche

Vous décidez à chaque étape

Claude propose, vous décidez. Rien n’est construit avant que vous ayez validé le plan. Ouvrez une étape pour en savoir plus.

1 Vous demandez

Tapez /compagnon-propose ou demandez simplement avec vos mots : « ajoute un mode sombre qui suit le réglage du système ».

Pour aller plus loin : Parler à Claude
2 Claude planifie

Claude étudie le code, puis écrit quatre fichiers courts : pourquoi, ce qui change, comment, et les tâches. Des relecteurs indépendants le relisent avant vous.

Pour aller plus loin : Un exemple de plan commenté
3 Vous validez

Lisez le plan, demandez des corrections, validez-le — dans la conversation ou sur GitHub. Sans terminal.

Pour aller plus loin : Relire un plan
4 Claude construit

Claude réalise les tâches dans l’ordre, lance chaque test et s’arrête au premier doute au lieu de deviner.

Pour aller plus loin : Réaliser et ranger
5 C’est rangé

Le plan rejoint les spécifications du projet : la personne suivante sait pourquoi le code est ainsi.

Démarrer

Installer Compagnon

Aucun outil de développement à installer. Les deux scripts vérifient l’empreinte SHA-256 du programme qu’ils téléchargent.

macOS et Linux

curl -sSL https://raw.githubusercontent.com/mairistem/compagnon/main/install.sh | sh

Windows (PowerShell)

iwr -useb https://raw.githubusercontent.com/mairistem/compagnon/main/install.ps1 | iex

Puis, dans votre projet : compagnon init

Ce que vous y gagnez

Le plan avant le code, des décisions qui tiennent

  • Des plans contestés avant votre relecture

    Des relecteurs indépendants — un sceptique, et des experts des domaines touchés — relisent le plan et vous soumettent au plus cinq points.

  • Les modifications sont des deltas

    Une modification ajoute, modifie ou retire des exigences des spécifications actuelles : Compagnon fonctionne sur du code existant, pas seulement sur un projet neuf.

  • Les décisions sont scellées

    Une décision d’architecture prend effet quand vous l’acceptez ; Compagnon scelle son texte, et la changer revient à la remplacer.

  • Documentation et tests dans chaque plan

    Chaque scénario est couvert par un test dans une tâche, et la documentation concernée est mise à jour dans une tâche.

  • La langue de votre équipe

    Les plans sont écrits dans la langue choisie par votre équipe ; leur structure reste lisible par les outils.

  • Mesuré, pas supposé

    Chaque modification des compétences est évaluée en qualité et en coût avant d’être publiée.
