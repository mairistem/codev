Choisissez votre parcours

Qu’allez-vous faire avec Compagnon ?

Choisissez la réponse la plus proche de ce que vous allez faire. Chacune ouvre un parcours court, de trois pages au plus.

  • Je relis et je valide des plans — je ne code pas

    Claude rédige un plan ; vous vérifiez qu’il dit la bonne chose, demandez des corrections, puis le validez. Sans terminal.

  • Je ne code pas, mais je veux que Claude construise quelque chose pour moi

    Vous décrivez votre idée avec vos mots, validez le plan de Claude, et Claude la réalise.

  • Je suis développeur et je fais coder Claude

    Une première modification en dix minutes, puis comment demander chaque étape.

  • J'installe Compagnon pour mon équipe

    Installation, vérifications sur le projet partagé, qui relit les plans et le code.

Démarrer

Installer Compagnon

Aucun outil de développement à installer. Les deux scripts vérifient l’empreinte SHA-256 du programme qu’ils téléchargent.

macOS et Linux

curl -sSL https://raw.githubusercontent.com/mairistem/compagnon/main/install.sh | sh

Windows (PowerShell)

iwr -useb https://raw.githubusercontent.com/mairistem/compagnon/main/install.ps1 | iex

Puis, dans votre projet : compagnon init

Fonctionnement

Le plan avant le code, des décisions qui tiennent

Chaque modification suit le même cycle — proposer, réaliser, synchroniser, archiver — avec une compétence Claude Code par étape.

  • Des modifications par écarts

    Une modification déclare les exigences qu’elle ajoute (ADDED), modifie (MODIFIED), retire (REMOVED) ou renomme (RENAMED) par rapport aux spécifications actuelles : Compagnon fonctionne sur du code existant, pas seulement sur de nouveaux projets.

  • Des décisions acceptées et scellées

    Une décision d’architecture prend effet quand vous l’acceptez ; Compagnon scelle son texte par une empreinte, et la changer revient à la remplacer.

  • Des plans relus avant votre relecture

    /compagnon-propose vérifie la traçabilité, relit le plan en sceptique, avec les experts des domaines touchés, et vous remet au plus cinq points à discuter.

  • Documentation et tests dans chaque plan

    Chaque scénario est couvert par un test automatique dans une tâche, et la documentation touchée est mise à jour dans une tâche.

  • La langue de votre équipe

    Les plans sont rédigés dans la langue choisie par votre équipe ; leur structure reste lisible par la machine.

  • Des conventions partagées

    Un projet peut hériter, en lecture seule, du contexte, des règles et des décisions d’un dossier partagé ou d’un dépôt git figé à un enregistrement (commit).

  • Un projet complet dès compagnon init

    Les compétences, CLAUDE.md et, sur GitHub, une vérification automatique et un modèle de demande de fusion ; compagnon doctor vous dit ce qui manque encore.

  • Des notes de version générées

    Chaque proposition porte sa note de version ; compagnon changelog rassemble celles des modifications archivées depuis la dernière version.

  • Les mises à jour en une commande

    compagnon self-update installe la dernière version après avoir vérifié son empreinte, puis rafraîchit les compétences du projet.

Compagnon est développé avec Compagnon

Chaque modification de ce dépôt est planifiée, relue et archivée avec l’outil lui-même, et chaque demande de fusion lance compagnon validate --strict. Son dossier _compagnon/ est un exemple réel à parcourir.
