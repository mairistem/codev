Spec-driven development for Claude Code.

codev adds a thin layer of specifications to your repository, so that you and Claude Code agree on what must be built before a line of code is written — and so that architecture decisions, once made, stop being re-debated on every change.

Getting started

Install codev

No Rust toolchain needed. Both scripts verify the SHA-256 of the binary they download.

macOS and Linux

curl -sSL https://raw.githubusercontent.com/mairistem/codev/main/install.sh | sh

Windows (PowerShell)

iwr -useb https://raw.githubusercontent.com/mairistem/codev/main/install.ps1 | iex

Then, in your project: codev init

How it works

Plans before code, decisions that hold

Every change follows the same cycle — propose, apply, sync, archive — with one Claude Code skill per step.

  • Changes are deltas

    A change declares ADDED, MODIFIED, REMOVED or RENAMED requirements instead of rewriting specs, which makes codev work on existing code, not only on new projects.

  • Decisions are sealed

    Accepted ADRs are sealed with a hash; changing one means superseding it, and codev validate catches silent edits.

  • Your team’s language

    Artifacts are written in the language your team sets; their structure stays machine-readable.
