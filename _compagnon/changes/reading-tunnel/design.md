# Design: One reading tunnel instead of reader profiles

## Context

- The books (`docs/en`, `docs/fr`, mdBook 0.5.4) have, since
  `2026-11-27-jira-and-modern-docs`, five parts — Start here (introduction,
  Choose your path, four path pages, glossary), Everyday use, Going
  further, Reference, Contributing — 38 chapters per edition. mdBook's
  previous/next buttons follow `SUMMARY.md`, so the reading order is the
  table of contents.
- The checks in `crates/compagnon-cli/src/docs_checks.rs` encode that
  structure: `START_HERE`, `PATHS`, `PARTS_AFTER_START`, `EVERYDAY`,
  `PROFILE_GUIDES`, `profile_labels`, `choose_path_problems`,
  `path_page_problems`, `missing_path_links`, the profile and path tests,
  `no_chapter_is_removed`; `tests/repository.rs` checks the READMEs' and
  home pages' profile links and the codev guide.
- The home pages are generated by
  `_compagnon/changes/archive/2026-11-27-jira-and-modern-docs/site/build_home.py`
  (four profile cards, Jira band, workflow, inside a plan, install).
- The offline manual (`docs.rs`) concatenates the chapters in
  `SUMMARY.md` order and rewrites `*.md` links to in-page anchors; it does
  not rewrite `*.html` links.

## Goals / Non-Goals

Decisions in effect: 0014 (the product is named Compagnon). No other
decision constrains the documentation's structure.

**Goals**: a reader who starts at the introduction and clicks "next"
reads a story; anyone can skip what does not concern them with one clear
button; nothing in the books exists only for the past; GitHub only.

**Non-Goals**: no change to the commands (`compagnon init`'s GitLab job
stays, see the proposal), the skills or the configuration; no new
diagram beyond the tunnel's own; the reference chapters keep their
content apart from removing GitLab and links to removed pages;
`reliability.md` stays generated.

## Decisions

### Decision: The tunnel is approved on a clickable mockup first

The first task builds `mockup/` in the change folder: one page with the
tunnel's table of contents on the left (five steps, then the appendices
and Contributing, greyed), and, for each chapter, a card with its title,
its one-line purpose, its skip button if any, and its "Next step"; clicking
a card's "Next step" or a skip button moves to that card, so the owner can
walk the tunnel. It is published as a private page; the rewrite waits for
the owner's approval, and changes the owner asks for go to the mockup
first. The approved version stays in the change folder.

**Alternatives considered**: rewriting first and reviewing the published
books (rejected: the previous refactor showed the order is what the owner
judges, and it is cheap to change before the text exists).

### Decision: Where each piece goes

| `choose-your-path.md`, `paths/*.md` | removed; their sentence "who is it for" becomes skip buttons where it matters |
| `guides/start-from-nothing.md` | `installation.md`, section "Starting from nothing" / « Partir de rien », first |
| `installation.md` | Get started, step one |
| `quickstart.md` | Get started, step two |
| `skills.md` (Asking Claude) | Every day, first |
| `guides/mcp.md` | Every day, after Asking Claude |
| `guides/review-a-plan.md`, `guides/approve-a-plan.md` | Every day; the approval guide becomes GitHub only |
| `workflow.md` sections Apply, Sync, Archive | new `guides/build-and-file.md`, Every day, last |
| `workflow.md` (rest: the workflow, the plan's files, how a plan is built) | Understand, first |
| `concepts.md`, `guides/decisions.md`, `roles.md`, `guides/review-record.md` | Understand |
| `guides/existing-project.md`, `guides/team-rollout.md` | For your team |
| `guides/repository-integration.md` | `guides/team-rollout.md`, sections on what `compagnon init` writes and `compagnon doctor` |

| reference chapters, glossary, FAQ, example plan | Appendices |

Skip buttons, where a reader may not need the page: Installation's
"Starting from nothing" ("Already have Claude Code and a project? Skip
to …" stays inside the page as a heading link, not a button); Your first
change for readers who do not code ("Not for you? Skip to Reviewing a
plan"); Start from a Jira ticket ("No Jira? Skip to Reviewing a plan");
Approving a plan on GitHub; the whole Understand step from How it works
("Not for you? Skip to For your team"); Roles; each For your team
chapter. The mockup fixes the final list.

### Decision: "Next step" is a markdown section; the skip button a wrapped markdown link

Each tunnel chapter ends with `## Next step` / `## Étape suivante`
holding one markdown link to the next chapter, titled as it, and at most
one sentence. A skip button is a markdown link wrapped in an HTML block,
so that mdBook and the offline manual both rewrite its `.md` target:

```markdown
<div class="skip-step">

[Not for you? Skip to Reviewing a plan](guides/review-a-plan.md)

</div>
```

The theme (`mairistem.css`) and the offline manual's CSS (`docs.css`)
draw `.skip-step a` as a button (border, padding, arrow), with a visible
focus; it is a link, so keyboard and screen readers treat it as such.

**Alternatives considered**: an `<a class>` in raw HTML (rejected: its
`.html` target breaks in the offline manual, which rewrites only `.md`
links); a blockquote styled by position (rejected: fragile, and a quote
is not a control).

### Decision: Nothing kept for the past

Removed files are deleted, links to them rewritten to the page that now
holds the content, and no `[output.html.redirect]` is added, as the owner
asked. Tests and constants that exist only for removed pages are deleted,
not kept "just in case". The CHANGELOG keeps its history (it is a record,
not a page of the books).

### Decision: GitHub only

Every chapter, README and home page drops GitLab: the approval guide
describes GitHub's pull request; the review guide, the team guide and the
FAQ say "pull request" (French « demande de fusion ») without the GitLab
variant. A check greps for "GitLab". The CLI's GitLab job printed by
`compagnon init` is out of scope (proposal).

### Decision: The home pages show the five steps

`build_home.py` is copied into this change's folder and adapted: the four
profile cards become five step cards (same card style, the five step
colors taken from the Mairistem palette and the grey of the line token),
each linking the first chapter of its step; the question becomes
"Read the documentation in five steps". The Jira band, workflow, inside a
plan, install and features stay. The READMEs drop the profile list and
link the introduction.

### Decision: The checks follow the tunnel

In `docs_checks.rs`:

- `TUNNEL: [(&str part_en, &str part_fr, &[&str] chapters); 5]`,
  `APPENDICES`, `CONTRIBUTING` replace `START_HERE`, `PATHS`,
  `PARTS_AFTER_START`; `toc_problems` checks the seven parts against them;
- `next_step_problems(md, next, title_of)` and `skip_problems(md,
  position, title_of)`: the last section and the optional skip button of
  each tunnel chapter;
- the caps of the first three steps move to `TUNNEL[..3]`; the
  introduction and quickstart keep theirs;
- `removed_pages_problems`: no removed file in the chapter list, no link
  to one in chapters, READMEs, home pages, no redirect in `book.toml`;
- `gitlab_mentions`: every chapter, README and home page;
- removed: the profile and path functions and tests, `EVERYDAY` (replaced
  by the first three steps), `PROFILE_GUIDES`, the codev guide tests in
  `tests/repository.rs`; the home page and README checks in
  `tests/repository.rs` check the five steps and the introduction link.

Each new check comes with a failing example and lands in the task that
makes the content pass it.

## Risks / Trade-offs

- [Removing pages breaks outside links] → accepted by the owner (no
  legacy); the release note says it, marked BREAKING.
- [The tunnel is long for someone who only reviews plans] → skip buttons
  at the start of the pages they do not need; the home page's step cards
  let them enter at Every day directly.
- [Moving Apply/Sync/Archive out of How it works breaks anchors such as
  `workflow.md#archive`] → every link is grepped and rewritten in the same
  task; the offline manual test that every link lands on its heading
  catches the rest.
- [Large diff again] → the mockup fixes the order before any text moves;
  each task keeps the suite green.

## Migration Plan

Documentation only: published by the Pages workflow on merge. Rollback is
reverting the merge.
